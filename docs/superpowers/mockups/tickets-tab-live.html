1 · Every screen reads the mirror; the mirror is rewritten each pulse

Today the mirror is a record — swept for the Tickets tab — while the Floor, Backlog and the dispatcher all read the live world snapshot. This makes the mirror the one copy every surface reads, and the pulse the one thing that writes it.

  • A pulse writes what it saw. One sweep per pulse over the assignment filter, upserting by number — the same call the snapshot already makes, so no new provider traffic on the common path.
  • Closed means stop tracking, not delete. A row whose state left the open set is marked tracking='frozen' and the sweep skips it from then on. It keeps its last-read title, labels, state and parent, and the tab still shows it under Frozen. Deleting it would take the cost history and the verdict with it, and the close-out sweep recognises its own obligations by finding the item again.
  • Thaw is one condition, not a judgement: the tracker returns it in the open set again (reopened). The changed-since read still names it, so the next pulse un-freezes it.
  • The dispatcher does not read this table, and must not start. That line is the whole reason the mirror was safe to build: a rule that could see a frozen row would eventually dispatch onto a closed item, and nothing would look wrong. Rules keep deciding from the live snapshot.

2 · The table becomes a control — and that is a real change

The shipped tab states “nothing in it is a control that changes the world — a history you can edit from is not a history.” A watch switch on the row contradicts that sentence, so the sentence has to change with the code, in the same commit, in docs/spec/17-cockpit.md.

  • One control, and only on live rows. Watch/ignore, nothing else. A frozen row's switch is inert with a title saying why: there is nothing in the tracker left to tag.
  • It is the existing route, not a new one — POST /api/issues/:number/watch, the same call the Backlog's toggle makes, so the two surfaces cannot come to disagree about what a click means. Three-valued display, two-valued write: unwatched is a state you can leave, never one you can select.
  • A container cascades, and the row says so before you click. watchCascadeTargets tags every descendant; the row shows cascades to 9. A partial failure is reported on the row — “tagged 6 of 9” — because an operator told “watched” while three children kept the old tag has been lied to about what the harness will pick up.
  • Optimistic, then reconciled by the pulse. The switch shows pending until the next mirror write confirms it. Trusting the click alone would leave the tab claiming a tag the tracker refused.

3 · “Why is nothing on this?” — quoted, never re-derived

The refusal already exists as a pure function: isIssuePickupEligible returns {eligible, reasons[]}, and the funnel's route for the item says the rest. The tooltip ships those strings; it does not compute its own opinion. A lens that reasoned about pickup would be a second dispatcher, and the two would drift the first time a gate changed.

  • Only where the question makes sense. The marker is drawn for a live row that is watched and has no agent and no PR — the case an operator actually asks about. A frozen row has no reasons, because eligibility is a reading of the live world.
  • Quiet marker for a container: a Feature is never worked itself, its children are the work, and that is an explanation rather than a problem.
  • The reasons it can carry today, verbatim from the gates: tagged leave-alone; no watch tag; the watch tag was added by someone else (issuePickupRequireOwnLabel); a container type; a state outside pickupStates; assay not passed; plan awaiting approval; blocked on a human part; attempt cap reached.
  • Hover is not the only way to it. The same list is the row's expanded panel on click — a tooltip nobody can select text out of is where a stack trace goes to die.

4 · Parent feature, and the colour

The provider already resolves it: Issue.parent is the hydrated Feature, with three distinct values that must stay distinct on the row.

ValueMeansDrawn
a parentthe Feature this hangs offcoloured chip, number + name
nullan orphan — genuinely no parenthatched swatch, “no feature”
undefinedthe link could not be read, or the provider has no hierarchydotted “parent unreadable”

Folding unreadable into orphan would tell the reader this item belongs to no feature, which is a different and wrong thing to say about a link we simply could not fetch — the provider is already careful about exactly this, and the column must not undo it.

On “a random colour persisted in the db”

  • Persisted: yes. A colour that moved between sessions is worse than no colour — the whole value is that the same feature is the same colour every morning. One row per feature id in a small table the mirror owns, written on first sight.
  • Random: recommend not. A random hue at random lightness produces two failures with nothing to catch them — a colour that vanishes against --panel-2, and two features that land near-identical and read as one. Instead: a fixed ladder of twelve hues at one lightness and one chroma (drawn above), assigned next-least-used at first sight and then persisted. Same stability, no unreadable draws, and past twelve features the ladder repeats — which is honest, because a legend with forty colours is not a legend anyone reads.
  • The colour is never the only signal. Every chip carries the feature number and name too, so the column works for a colour-blind reader and in a screenshot pasted into a ticket.
  • The legend doubles as the filter and is a Place field (feature=118) — a narrowing you cannot link to or come back to with the back button is the cockpit's other repeated bug.

5 · States: the tracker's own words, on the deployments that have them

Issue.workItemState already carries the raw System.State beside the open/closed collapse, precisely so the pickup gate and the in-review back-off can see it. The filter stops throwing that away.

  • Two tiers, not one control. Tracking (live / frozen) is the harness's reading and is provider-independent; State is the tracker's own word. One control folding them would state a triage nobody made — Removed and Closed are both frozen and are not the same fact.
  • The state list is discovered, never hardcoded. It is the distinct set the mirror has actually seen, with counts. A hardcoded Azure ladder is wrong on the first customised process template, and silently — the missing state's items simply stop being reachable by any filter.
  • GitHub and the fake have no native states, so the second tier is not drawn at all and the coarse axis reads Open / Closed as it does today. A filter offering states the provider cannot produce is a control that always returns nothing.
  • The ▲ marks a state pickupStates lets through, read from config — the single most-asked question about an Azure deployment (“why is Ready worked and New not?”) answered where the states are, rather than in a settings pane nobody opens.

Where the pieces go

  • Store: src/store/tickets.ts keeps owning the table. New columns on an existing table — tracking, work_item_state, parent_number, parent_title, last_read_at — each need an additive ALTER TABLE entry in that module's ColumnMigrations, or they are invisible on every database from before today with nothing erroring. The feature-colour table is a fresh CREATE TABLE with an empty column list declared anyway.
  • Sweep: the pulse's mirror write gains the freeze rule and the parent columns. Still a record: nothing under src/dispatcher/ reads it, and test/workGraph.test.ts-style structural assertions are the place to say so.
  • Route: GET /api/tickets grows tracking, state (now a provider-native string), and feature; the response ships the discovered state list with counts, the feature legend with colours, and the per-row reasons. Wrapped in checked(...) as every handler is. The watch write reuses POST /api/issues/:number/watch — no new route.
  • Wire: TicketRow in src/wire.ts gains workItemState, tracking, parent, featureColor, pickupReasons. A wire type either is a domain type or extends it.
  • Place: tracking, state, feature join the tab's existing three fields in web/src/cockpit/place.ts — never a useState in useCockpit.
  • Panel: web/src/components/TicketsPanel.tsx. The switch is a control and the ticket number stays a <Ref> beside it in a cn-refs group — a reference never goes inside a button.
  • Specs, same change: 17-cockpit.md (the tab, the “no controls” sentence, the address bar), 16-http-api.md (the route), 14-persistence.md (the columns and the freeze rule), 15-integrations.md (parent hydration on the history read), 06-issue-pickup.md (the reasons being surfaced verbatim).

Open questions — worth settling before any of this is built

  • Does this replace the Backlog tab? With live rows, a watch switch and a state filter, this tab is a strict superset of Backlog. Two surfaces that can be told different things about the same item is the drift the shared watchLabels function exists to prevent — one of them should go, and it should probably be Backlog.
  • Does the mirror become the snapshot's source, or stay beside it? This mockup says every screen reads the mirror and the dispatcher keeps reading the live world. The stronger version — the world snapshot itself being built from the mirror — is a much larger change and puts a stale row one bug away from a dispatch. Recommend not, for now.
  • Hierarchy on the history read. listTicketHistory deliberately does not hydrate the parent, because that read is per-item and a month of backfill would cost a request per ticket. A parent column means paying it for live items at least. Cheapest honest version: hydrate parents for the open set only (already fetched for the snapshot), and leave frozen rows with whatever parent they were last seen with.
  • Freezing on Removed. Azure's Removed is not Closed — it means “this was never real”. Same freeze, but should it count in the tab's totals or the spend at all?
  • Cost on a frozen row still moves if a late run is attributed to it. Either the row is not truly frozen, or cost is read live and only the tracker fields freeze. The second is what this mockup draws.
